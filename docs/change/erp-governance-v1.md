# 制造业 ERP 框架准则（V1.0）

## 1. 目标与范围
- 目标：统一架构、数据、流程、交付质量，减少返工。
- 适用范围：主数据、计划、采购、生产、库存、质量、设备、财务。
- 优先级：安全合规 > 数据一致性 > 业务连续性 > 开发效率 > 个性化需求。

## 2. 执行红线
- 禁止直接在 `src/` 调试。
- 禁止跨域直接读写数据库。
- 禁止无审计日志的关键操作上线。
- 禁止无回滚方案发布。

## 3. 隔离开发流程
1. 在 `test_impl/` 开发与调试。
2. 运行 `scripts/verify.ps1` 执行 lint/test/checklist。
3. 发起评审并给出合规等级（A/B/C/D）。
4. 通过 `scripts/promote.ps1` 受控覆盖到 `src/`。
5. 异常时通过 `scripts/rollback.ps1` 回滚。

## 4. 合规判定
- A：准则内，直接开发。
- B：准则内扩展，补充设计后开发。
- C：触碰红线，需评审签字。
- D：违反准则，默认驳回。

## 5. 审计留痕要求
- 每次覆盖必须记录：变更单 ID、审核人、测试结果、覆盖清单、回滚包 ID。

## 6. 变更日志与 SOP 同步（强制）
- 每一次变更都必须在《变更日志》登记：`docs/change/CHANGELOG.md`。
- 凡影响操作步骤、界面、启动方式或业务规则的变更，必须**同步**更新《系统操作 SOP》：`docs/SOP/系统操作SOP.md`。
- 里程碑发布须同步更新《版本记录》：`docs/VERSION.md`。
- Web 界面须遵循《UI 设计基线》：`docs/design/ui-style-guide-v1.md`；扩展或偏离须登记变更并更新基线文档。
- 变更日志条目须标注 "SOP 同步" 状态（已更新 / 不涉及）。
- 未登记变更日志或未同步 SOP 的改动，判定为 **D（违反准则）**，默认驳回。
- 本规则对所有后续变更生效；我在每次改动完成后会主动提示是否已同步两份文档。
