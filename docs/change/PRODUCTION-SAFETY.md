# WKT · 生产环境安全规范（强制）

> **阶段**：测试 / 交付 — **云端 = 正式生产数据**（真实订单、料号、外协等）。  
> **本地**：开发调试；**只上传程序代码**，不上传/覆盖云端业务库。  
> Agent 与人工开发 **必须**遵守；违反须主动告警，不得 silent 输出危险代码。

---

## 1. 允许的运维入口（仅 3 个 bat）

| 文件 | 作用 | 数据影响 |
|------|------|----------|
| `一键启动网页.bat` | 本地启动 Flask | 仅本地 |
| `一键推送云端和GitHub.bat` | Git 推送 + **代码**部署云端 | **不**覆盖云端 `data/` 业务库 |
| `一键下载云端数据覆盖本地.bat` | 云端 → 本地 `data/`（本地先备份） | **覆盖本地**，不动云端 |

**已废弃/删除**：全量同步云端、查询云端、恢复云端供应商、写入 SOP 测试数据、单独 GitHub/同步 bat 等。

---

## 2. 代码边界（硬性）

### 2.1 严禁产出

- 清空数据表、TRUNCATE、DROP 业务表
- 批量重置业务单据、无条件批量 UPDATE 业务表
- **全量覆盖**云端/本地生产 `data/`、`wkt_orders.db`、客商 JSON
- 上传/同步**本地数据库至云端**的逻辑（`-FullData`、`-WithMasterData` 已禁用）
- 硬编码云端生产数据库连接地址

### 2.2 仅允许

- 迭代 **程序代码**（`test_impl`、`scripts`）
- **增量** schema 迁移（只 ADD COLUMN / 新表，不毁存量）
- 本地调试默认连接 **本地** `data/wkt_orders.db`

---

## 3. 数据库变更

- 只生成 **增量迁移**（`ALTER TABLE ADD COLUMN`、新表、索引）
- **禁止**销毁/覆盖存量数据的 SQL
- 数据修复脚本须标注：**【严禁直接在生产一键执行，需要人工核对】**

---

## 4. 高危操作保护

任何 **删除、批量修改** 数据的 API/函数须：

1. **环境判断**：生产环境需二次确认或禁止自动执行  
2. **操作日志**（审计表 / feishu audit）  
3. 不得无防护直接暴露给前端一键执行  

---

## 5. 部署逻辑

- 用户手动运行 bat → 上传**代码包**到云服务器  
- **假定**：云端 `data/` 始终为权威；本地库 **不可**覆盖云端  
- 需要与生产一致的数据 → 用 **`一键下载云端数据覆盖本地.bat`**

---

## 6. 脚本层防护（已实现）

| 脚本 | 限制 |
|------|------|
| `scripts/sync-to-cloud.ps1` | `-FullData` / `-WithMasterData` **拒绝执行** |
| `scripts/push-cloud-and-github.ps1` | 仅 code-only 同步 |
| `scripts/pull-data-from-cloud.ps1` | 仅 **云→本地**，本地先 `data.local.bak-*` |

---

## 7. Agent 行为

生成方案/代码前自问：

1. 是否会写/删/覆盖 **云端** 业务数据？→ **停止并告警**  
2. 是否同步本地 DB 到云？→ **禁止**  
3. 是否缺少迁移而要求删表重建？→ 改为增量迁移  
4. 修复脚本能否在生产误点？→ 加标注 + 确认门  

触碰任一条：**先提醒用户风险**，不得直接输出可执行危险代码。
