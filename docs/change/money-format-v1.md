# WKT 金额格式统一标准 v1

> 全系统强制遵循。单一实现来源：`test_impl/common/money.py`。
> 任何模块涉及金额/单价/税额/汇率，必须复用该模块，禁止各自实现。

## 1. 存储 / 代码层（精度优先，严禁 float）
| 维度 | 规则 |
|------|------|
| 数据库类型 | `DECIMAL/NUMERIC`，禁止 `float/double` |
| 金额（金额/税额/折扣/合计） | `DECIMAL(18,2)`，2 位小数 |
| 订单数量（PO / 已出货 / 未结） | `DECIMAL(18,1)`，1 位小数 |
| 单重 g（数字） | `DECIMAL(18,2)`，2 位小数 |
| 单价（含税/未税、物料单价） | `DECIMAL(18,4)`，4 位小数 |
| 汇率 | `DECIMAL(12,6)`，6 位小数 |
| Python | `decimal.Decimal`，不用 `float` |
| 前端 / JS | 仅展示与录入；金额计算以后端为准（前端预览不作为最终值） |

## 2. 舍入
- 统一财务四舍五入 `ROUND_HALF_UP`，统一到对应小数位，**禁止截断**。
- 实现：`round_amount`（2 位）/ `round_qty`（1 位）/ `round_weight`（2 位）/ `round_price`（4 位）/ `round_rate`（6 位）。

## 3. 展示格式（UI / 报表 / 单据）
- 千分位分隔；**整数不写小数**（如 `5,000`、`1,407,510`），有小数则保留（如 `12,345.67`、`2,996.9`）。
- 负数财务写法：`-12,345.67`。
- 大写金额（财务单据/发票/凭证）：`rmb_upper`，示例 `12345.67 → 人民币壹万贰仟叁佰肆拾伍元陆角柒分`、`10000.00 → 人民币壹万元整`。
- 实现：`fmt_amount` / `fmt_price` / `fmt_rate` / `rmb_upper`。

## 4. 输入框
- 仅允许数字、小数点；最多 1 个小数点。
- 小数位上限：数量 1 位、单价 4 位、金额 2 位（前端 `attachDecimalLimit`）；单重数字 2 位（保存时后端规范化）。
- 失焦展示可补千分位与固定小数（展示态）。

## 5. 接口 / 报文（对外对接）
- 传输用**纯数字字符串**，**无千分位、无货币符号**；整数不写小数点：`1407510`、`2996.9`。
- 实现：`serialize_qty` / `serialize_amount` / `serialize_price`；`transport` 保留用于固定小数位兼容。

## 6. 业务字段口径
| 字段 | 存储 | 展示 |
|------|------|------|
| 订单数量（PO、已出货、未结） | DECIMAL(18,1) | 1,234.5 |
| 单重 g（数字） | DECIMAL(18,2) | 120.50 |
| 单价（含税单价、物料单价、工艺单价、单件成本/报价） | DECIMAL(18,4) | 1,234.5678 |
| 金额（行金额、订单合计、应收应付、对账） | DECIMAL(18,2) | 12,345.67 |
| 税额 | DECIMAL(18,2) | 1,234.56 |
| 折扣/优惠 | DECIMAL(18,2) | -500.00 |
| 汇率 | DECIMAL(12,6) | 7.123456 |

> 说明：成本分析的「单件成本/客户报价」按**单价口径（4 位）**展示与存储。

## 7. 落地现状（v1）
- 订单：行金额、订单合计 2 位；含税单价 4 位；接口传输纯字符串；订单合计返回大写。
- 成本分析：单价/单件成本/报价 4 位。
- 前端：金额/单价统一千分位 + 固定小数；订单合计展示大写；录入框限制小数位。
