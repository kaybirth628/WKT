# WKT · Agent 变更合规指南

> **强制**：凡 Agent 改动代码（含 UI、后端、测试），**同一任务内**完成下列登记；未完成视为 **不合规**。  
> 用户要求：**每次变动** 记 CHANGELOG、**用户可见变更** 同步 SOP、**Bug 修复** 记根因以防复发。

---

| 文档 | 编号 | 何时写 |

## 2. 任务结束前 Checklist（逐项打勾）

```
[ ] CL-XXXX 已写入 CHANGELOG.md 顶部（递增、不复用）
[ ] 若类型=修复 → BF-XXXX 已写入 BUG-FIX-LOG.md
[ ] 若用户可见流程变化 → SOP 已更新，CL 表内「SOP 同步」= 是
[ ] 若仅内部/Agent 文档 → CL「SOP 同步」= 否，并写「SOP 免同步原因」
[ ] 若改 UI 布局 → UI-XXXX 已登记
[ ] 若改库/API 字段 → data-model.md 已同步
[ ] 相关测试已跑（或说明未跑原因）
[ ] 若改后端/静态资源 → build / ?v= 已 bump
[ ] 回复用户时列出 CL（及 BF/SOP 是否已同步）
```

**禁止**：改完代码不登记 CL；修复 Bug 不写根因；用户可见改动标「SOP 同步：否」却不写原因。

## 3. CHANGELOG 登记（CL-XXXX）

### 3.1 格式（在 `CHANGELOG.md` 顶部追加）

```markdown
### CL-XXXX · YYYY-MM-DD · 类型（合规等级）

| 字段 | 内容 |
|------|------|
| 涉及模块 | 文件/子系统 |
| 变更内容 | 做了什么（用户视角 + 技术要点） |
| 根因 | **修复类必填**；其他类型可填「—」 |
| 防复发 | 测试/规则/文档如何防止再犯 |
| 验证 | 命令或操作步骤 |
| SOP 同步 | 是 / 否 |
| SOP 免同步原因 | 仅当「否」时填写 |
| 关联 | BF-XXXX / UI-XXXX / CL-YYYY（可选） |
```

### 3.2 类型与合规等级

| 类型 | 说明 |
|------|------|
| 新增 | 新功能、新 API、新页面 |
| 优化 | 体验/性能/重构（无 Bug 报告） |
| 修复 | Bug、回归、数据错误 |
| 重构 | 行为不变的结构调整 |
| 文档 | 仅文档/规则（无代码） |

等级 A/B/C/D：见 [`erp-governance-v1.md`](erp-governance-v1.md)（沿用项目惯例）。

## 4. SOP 同步规则

### 4.1 必须同步 SOP（「SOP 同步 = 是」）

- 新增/删除/改名：菜单、按钮、录入步骤、必填字段
- 用户操作顺序变化（如 BOM 先选模式再上传）
- 业务规则变化（如「同料号覆盖」、查询排序）
- 常见问题的新解法（可同步更新 **§七 常见问题**）

### 4.2 可不同步 SOP（「SOP 同步 = 否」+ 原因）

| 原因示例 | 说明 |
|----------|------|
| 仅 Agent/开发文档 | `AGENTS.md`、`.cursor/rules`、设计规范 |
| 纯内部重构 | 用户界面与操作步骤完全不变 |
| 仅测试/CI | 无用户可见变化 |
| 纯样式微调 | 按钮位置不变、流程不变（仍记 UI-CHANGELOG） |

### 4.3 SOP 编辑位置

| 内容 | 文件章节 |
|------|----------|
| 日常操作 | `docs/SOP/系统操作SOP.md` 对应模块 § |
| 常见问题 | §七 |
| 图文培训 | 大改时酌情更新 `员工培训手册-图文版.md` |

同步后更新 SOP 文末 *文档版本* 与 *更新日期*。

## 5. Bug 修复日志（BF-XXXX）

**凡 CL 类型 = 修复**，必须在 [`BUG-FIX-LOG.md`](BUG-FIX-LOG.md) 追加 **BF-XXXX**（与 CL 同任务）。

### 5.1 格式

```markdown
### BF-XXXX · YYYY-MM-DD

| 字段 | 内容 |
|------|------|
| 关联 CL | CL-XXXX |
| 模块 | |
| 现象 | 用户看到什么 / 什么操作失败 |
| 根因 | 为什么发生（代码/数据/误解） |
| 修复 | 改了什么 |
| 防复发 | 单测名、规则、SOP §、代码注释 |
| 验证 | |
```

### 5.2 Agent 修 Bug 前

1. 读 `BUG-FIX-LOG.md` **全文索引**或按模块 grep，确认是否 **已修复过**
2. 若重复出现：对照原 BF 的「防复发」是否失效，**不要**只做表面 patch

### 5.3 修 Bug 后

1. 新增 BF-XXXX
2. CL 中填写 **根因**、**防复发**、**关联 BF-XXXX**
3. 若用户需知晓 → SOP §七 或对应操作 § 补充一句

## 6. 与其他日志的关系

```
用户报 Bug
  → 查 BUG-FIX-LOG（是否老问题）
  → 修复代码 + 测试
  → BF-XXXX + CL-XXXX（修复）
  → SOP（若用户可见）
  → UI-CHANGELOG（若改布局）

新功能
  → CL-XXXX（新增）
  → SOP 操作 §
  → data-model（若持久化）
  → UI-CHANGELOG + ui-layout-rules（若新 UI 范式）
```

---

## 7. 回复用户时的最小报告

每次 Agent 完成改动，回复中须含：

- **CL-XXXX**（及 BF-XXXX 若适用）
- **SOP**：已同步 / 免同步（原因）
- **测试**：条数或命令
- **重启**：是否需要 bat + Ctrl+F5
