# WKT 销售管理系统 - 订单管理模块准则（V1.0）

## 1. 模块范围
订单管理模块由以下六个子模块构成：
- 成本分析
- 订单录入
- 出货明细
- 对账
- 未结订单
- 结案订单

## 2. 领域边界（强制）
- 本模块负责：订单从录入到结案的全生命周期管理及经营分析。
- 本模块不负责：采购、库存底层台账、财务总账记账引擎（仅输出对账结果/凭证数据）。
- 与外部域交互：必须通过接口或事件，禁止跨域直连数据库。

## 3. 子模块定义

### 3.1 订单录入
- 职责：创建与维护订单头、订单明细、客户与交付信息。
- 关键规则：
  - 订单号唯一且不可复用。
  - 明细金额 = 数量 * 单价（含折扣逻辑后形成应收金额）。
  - 订单创建后进入 `draft`，审核通过后进入 `approved`。
  - 禁止跳过审核直接出货（例外需 C 级审批）。

### 3.2 出货明细
- 职责：记录每次出货的批次、数量、时间、责任人、物流信息。
- 关键规则：
  - 出货数量累计不得超过订单未出货量。
  - 每次出货必须关联订单明细行。
  - 出货成功后更新订单履约进度。

### 3.3 对账
- 职责：按客户、订单、周期进行应收与实收核对。
- 关键规则：
  - 对账单必须可追溯到订单、出货、回款记录。
  - 差异必须标记原因码并进入待处理队列。
  - 对账完成后才允许进入结案候选。

### 3.4 未结订单
- 职责：管理未完成履约或未完成回款的订单池。
- 关键规则：
  - 未满足“出货完成 + 对账完成 + 关键异常关闭”的订单均归类未结。
  - 支持按账龄、客户、销售员、区域进行优先级排序。

### 3.5 结案订单
- 职责：归档满足结案条件的订单，形成不可变历史记录。
- 关键规则：
  - 结案条件：出货完成、对账完成、无未关闭差异。
  - 结案后业务字段只读，需反结案必须走审批。
  - 结案操作必须有审计日志。

### 3.6 成本分析
- 职责：基于订单维度统计收入、成本、毛利、毛利率。
- 关键规则：
  - 分析口径版本化，变更必须记录生效时间。
  - 结果需可追溯到源单据（订单、出货、费用）。
  - 分析数据不允许反写业务单据。

## 4. 订单状态机（统一）
- `draft`（草稿）
- `approved`（已审核）
- `partially_shipped`（部分出货）
- `shipped`（完成出货）
- `reconciled`（已对账）
- `closed`（已结案）
- `cancelled`（已取消）

允许流转：
- `draft -> approved | cancelled`
- `approved -> partially_shipped | shipped | cancelled`
- `partially_shipped -> shipped | cancelled`
- `shipped -> reconciled`
- `reconciled -> closed`

禁止流转：
- 任何状态直接跳转 `closed`
- `closed -> 其他状态`（反结案需审批流程）

## 5. 核心数据对象（最小集合）
- `sales_order`：订单头
- `sales_order_item`：订单明细
- `shipment_record`：出货记录
- `reconciliation_record`：对账记录
- `order_cost_fact`：订单成本分析事实表
- `order_audit_log`：订单审计日志

## 6. 发布门禁（本模块）
- 代码修改必须在 `test_impl/` 完成。
- 通过 `scripts/verify.ps1` 基础检查。
- 至少通过以下业务用例：
  - 新建订单并审核通过
  - 分批出货直到完成
  - 对账差异识别并关闭
  - 未结订单转结案订单
  - 成本分析结果可追溯
- 通过后方可执行 `scripts/promote.ps1`。

## 7. 合规判定规则（用于后续需求）
- A：不改变状态机和数据红线的新增/优化。
- B：扩展字段或报表口径，补充设计即可。
- C：触碰状态机红线或跨域边界，需评审签字。
- D：要求绕过审核、绕过对账、直接改 `src/`，默认驳回。
